# 一句话说：这是给 DSH 用的「省 token」方案

**一句话版本：** AI 每回答一次，都要把你们之前说过的所有话**从头再读一遍**。所以对话越长，每一句都越贵。这套东西的作用就是——**别让没用的内容进入对话**。

本文不需要任何技术背景。技术版：[`intro-professional.zh.md`](intro-professional.zh.md) ｜ English: [`intro-beginner.en.md`](intro-beginner.en.md) / [`intro-professional.en.md`](intro-professional.en.md)

---

## 打个比方

把 AI 想象成一个**记性很差但很聪明的助手**。

你问他一个问题，他要从头读一遍你们**全部**的聊天记录才回答。你说下一句，他又从头读一遍。聊得越久，他每一句都要多读越多。

```
第 1 句：读 1 页        💰
第 2 句：读 2 页        💰💰
第 3 句：读 4 页        💰💰💰💰
... 一直翻倍下去
```

所以真正烧钱的**不是**「AI 读了多少新东西」，而是**「旧内容被反复读了多少遍」**。

**实测数据（不是估算）**：我们有个会话，助手一共回答了 **672 次**，累计读了 **2.87 亿个 token**。最典型的一次请求，他要重读 **25 万个 token**——而其中绝大部分是**旧聊天记录**。

### 一个反直觉的事实

DSH 有个「缓存」功能：重复读过的内容，第二次读会便宜 50 倍。

**但便宜不等于免费。** 我们实测：**99.3%** 的内容都命中了缓存，可账单里**仍然有一半（50%）是花在「重读缓存」上**。

> 所以结论是：**靠缓存省不了钱。要靠「让内容压根别进去」。**

## 这套方案做了什么（四个动作）

### 动作一：太长的输出，先「抄个开头结尾」再放进对话 ⭐ 最值钱

比如你让助手列一下某个文件夹里所有文件，结果出来了 **6 万字节**的一长串。

**原来的做法**：整串塞进对话。此后**每一次**回答，都要把这 6 万字节重读一遍。

**现在的做法**：对话里只留「开头几行 + 结尾几行 + 一句说明：全文存在这个文件里」，一共约 **1.1 万字节**。需要细节时再去文件里翻。

**实测效果**：

| 门槛 | 能挡下多少内容 |
|---|---|
| 出厂设置（5 万字节） | 1,918 条里只挡下 **1 条** —— 等于没开 |
| 本方案（1.2 万字节） | 挡下 **39 条，占所有工具输出的 33%** |

**这是整套方案里最值钱的一项**，而且它只是个配置数字，不是插件功能。

### 动作二：大块文本交给「免费助手」加工，只把结论带回来

需要从一大段文字里提炼要点时，不要把原文丢进对话，而是**交给一个免费的模型**去做，只把**结论**放回对话。

**实测**：一次 2,689 字符的原文 → 只带回来 **74 字符**的结论。而此后被反复重读的，只是那 74 字符。

### 动作三：免费服务忙的时候，自动换一家

免费模型有每分钟的用量上限。一到上限就报错（429）。

**实测发现**：**额度是按「模型」分别计算的，不是按账号共用的。** 我们把一个模型用到上限（22 秒烧掉 22 万 token 后报 429），紧接着另外三个免费模型**立刻都正常返回**。

所以：一家忙就换一家，**大约 1 秒**就绕过去，不用等一分钟。6 个免费模型合计约 **30 万 TPM** 的容量。

### 动作四：能算出钱到底花在哪

附带了几个小脚本，读你自己的会话记录，算出真实账单构成。**因为「凭感觉猜」会猜错方向。**

## 还有一件最重要、但不花钱的事

**少问几次、问准一点。**

实测每轮对话触发的请求数：

| 会话 | 你说几句话 | 助手内部请求了几次 | 每句话平均 |
|---|---|---|---|
| 一个会话 | 50 句 | 672 次 | 13.4 次 |
| 另一个 | **1 句** | **84 次** | **84 次** |

同一套工具，有人一句话触发 13 次，有人一句话触发 84 次。**每次多余的调用都要重读一遍全部历史。**

所以：**想清楚再动手、别反复读同一个文件、能一次问完的不要拆成五次。** 这条不花钱，但效果最大。

## 怎么用（三步）

```sh
# 1. 装进 DSH 的一个 profile
dsh plugin --profile web add <这个项目的路径>

# 2. 抄一份配置（二选一）
#    templates/profile-patch.hosted.yml      用免费在线模型 + 本地兜底
#    templates/profile-patch.local-only.yml  只用本地模型

# 3. 重启 DSH，然后自检
node tools/doctor.mjs
```

**第 2 步不能省。** 只装插件几乎不会省钱——真正起作用的是那个「挡下大块输出」的配置数字。

## 它不做什么（避免误会）

- **不换你的模型**，也不降低回答质量；
- **不是免费替代品**。付费模型仍是主力，只是让它少花点；
- **不需要显卡**（用免费在线模型的话）。本地模型是可选项，是免费额度用光后的兜底。

## 已知的代价（实话）

- 如果用本地模型，**在低显存的家用设备上会很慢**：本机（8GB 显存的消费级 A 卡）实测约每 1,000 字 1 秒多。
  **这一条高度依赖硬件**，显存更大的机器会明显更快 —— 别把本机的数字当成通用结论。
- 免费额度有上限，重度使用会碰到。
- 「抄开头结尾」意味着 AI 第一眼看不全那段输出；需要细节时它得再去翻文件（通常它不需要）。

## 怎么确认它真的生效了

```sh
node tools/doctor.mjs        # 检查配置有没有正确套上、依赖有没有变化
```

它会告诉你：配置行还在不在、插件有没有正常加载、密钥能不能取到、有没有编码损坏。出问题会明确报错，不会静默失效。

## 一个诚实的小故事

项目第一版有个 bug：**配置看起来完全正确，但每次调用免费模型都失败**（返回「密钥无效」）。

原因很隐蔽：DSH 把密钥存在一个文件里，但**不会**把它设成环境变量，而插件当时只会去读环境变量——于是读了个空，发出去一个假的密钥。

**这个 bug 已修好**（改成直接读那个文件），并且自检脚本现在会专门检查这一项。写在这里是想说明：这套东西的价值不只在「想到了什么」，也在于**把踩过的坑变成能自动发现的检查**。
